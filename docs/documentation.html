    Formats & hosts

    Freally MIDI Master is a CLAP plugin. VST3 and AU are projected from it rather than implemented separately, which is what makes it loadable in hosts that do not speak CLAP.

    Host Format Status
    Ableton Live 12 VST3 Loads and generates
    FL Studio CLAP Loads and generates
    Reaper · Bitwig · Logic CLAP / VST3 / AU Not yet tested
    No DAW Standalone Runs in its own window

    The plugin is a MIDI generator. It emits notes onto the track you inserted it on; the instrument you have loaded there makes the sound.

    Installing

    ⛔ Downloads open at 1.0. There is no installer, no beta and no preview build before then — a plugin that half-works inside somebody's session is worse than one that is not there, so it ships when the QA matrix is green on every host and every OS.

    Until then it builds from source, which is a supported path rather than a workaround — see Building from source. npm run plugin:install links the build straight into your CLAP folder.

    Where the formats live, once 1.0 lands:

    OS CLAP VST3
    Windows %COMMONPROGRAMFILES%\CLAP %COMMONPROGRAMFILES%\VST3
    macOS ~/Library/Audio/Plug-Ins/CLAP ~/Library/Audio/Plug-Ins/VST3
    Linux ~/.clap ~/.vst3

    The core loop

    1. Pick someone. Search an artist, or click a genre chip.
    2. Generate. The pattern is built for your project's tempo and key.
    3. Hear it. Press play in your DAW — the notes are already on the track.
    4. Reroll or keep. Every generation carries a seed you can copy back.

    The roster

    Most MIDI generators think in genres. "Trap" is not "Metro Boomin," and no mainstream tool has heard of OsamaSon. Freally MIDI Master thinks in artists — each one a set of hand-authored style parameters describing hat-roll grammar, 808 slide behaviour, swing, register and section layout.

    Search is instant fuzzy autosuggest across a mainstream roster and an underground roster. Genres are a browse filter, not the unit of generation — though a genre is itself a real style model and generates in its own right.

    Artist names are descriptive style references only. Nothing in the dataset is copied MIDI, sampled audio, or a transcription of anyone's record.

    The generators

    Five part generators, plus Song Mode. Song Mode is not a sixth generator — it lays out an arrangement and fills the other five in.

    Tab What it makes
    Drums Kick, snare/clap, hats with roll grammar, percussion, and the 808 line
    Melody Phrase structures — riff loop, question/answer, call/response, long arc — with chord-tone bias on strong beats and per-genre devices
    Countermelody Octave echo, bell echo, arpeggio, answer lick and sustained pad, placed in the melody's gaps
    Bassline The low end, locked to the drums' 808 behaviour
    Chords Progressions in the session's key and scale
    Song An arrangement that fills the five above in — a mode, not a generator

    What generates in the plugin today: drums and chords. Melody, countermelody and bassline exist in the engine and are being wired through — the plugin says so plainly rather than returning an empty grid.

    Pitches are chosen as scale degrees and only then turned into MIDI notes, so staying in key is structural rather than filtered for afterwards.

    Tempo, key & auto-sync

    The plugin reads the host's tempo and time signature every block. Trap authored at 140 comes out at 92 in a 92 BPM project — because a clip generated at the artist's tempo does not fit the song you asked for.

    Precedence

    1. Your pin wins. Pin a tempo in the session chips and it beats everything.
    2. Then the host. With auto-sync on, the DAW's tempo is used.
    3. Then the artist. With auto-sync off, the model's own authored tempo stands.

    Auto-sync is a session setting saved with your project — three states, not two. Turning it off is how you reach the artist's authored tempo from inside a running project.

    Seeds & reproducibility

    Every generation has a seed. The same seed, artist and session always produce a byte-identical pattern — on any machine, on any day. Copy the seed from the chip, paste it back, and the beat returns.

    Leave the seed box empty to get a fresh one each time; the chip then shows the seed that was actually used, so you can copy a generation you liked even though you never typed a number.

    Determinism is enforced by the test suite, not merely intended — it is also why a saved project can restore a beat without storing a single note.

    Presets

    A preset is a named session — artist, seed, bars and pins. Factory presets are compiled into the binary; your own are written to the platform's per-user data directory, so they outlive any one project.

    No factory preset pins a tempo. A pin is an instruction from the user, and a shipped file is not the user — a factory preset that pinned one would override your DAW the moment you loaded it.

    Session state

    The plugin saves your artist, seed, bars, pins and window size into the DAW's own project file. Reopen the song and the session comes back. There is no file to manage and no path to choose.

    The pattern itself is not stored — the inputs are, and the engine is deterministic, so restoring is a regeneration. That is why a saved project costs bytes instead of hundreds of kilobytes of notes.

    Keyboard shortcuts

    Keys Action
    K Show or hide the right rail
    Ctrl/⌘ + Z Undo
    Ctrl/⌘ + Shift + Z Redo
    Ctrl + Y Redo (Windows)

    Undo is unlimited within a session and covers the artist, seed, bars, pins and each generation. Inside a text field your system's own undo takes the shortcut, so the seed box can still un-type a character.

    The standalone

    The same plugin, in its own window, with no DAW involved — useful for trying things quickly and for machines where you are not producing.

    It cannot sync to your DAW, and it never will — there is no host, so there is nothing to sync to. A fixed tempo can be set on the command line, which exercises the same path, but real host tempo, meter and playhead need a real host.

    Privacy & the network

    No accounts. No telemetry. Nothing about you, your projects or your output is transmitted. Generation, playback, import and export are entirely local.

    No outbound connections exist. The desktop app had exactly two — a launch-time update check and an opt-in crash report — and both were removed with it. The plugin is installed and updated by whoever installs plugins, and no HTTP client is compiled into it. A build gate checks this on every commit rather than trusting the claim.

    Reporting a bug

    The in-app crash reporter belonged to the desktop app and went with it. A plugin lives inside someone else's process: when it takes the host down there is no window of ours left to draw a dialog in, and the report a producer needs to send is the DAW's own crash log, not ours.

    So report a crash the ordinary way — open an issue on the repository, and say which host, which format (CLAP or VST3) and which OS version. Attach the log your DAW wrote if it wrote one.

    Building from source

    Prerequisites: Rust (the version in rust-toolchain.toml) and Node.js 20+.

    Command What it does
    npm install Install the frontend toolchain
    npm run plugin:standalone The plugin in its own window, no DAW needed
    npm run plugin:build Release .clap, with the bundled-content gate
    npm run plugin:install Symlink it into the CLAP folder — once
    npm run ci:local Every gate, with CI's own environment

    npm run build must run before any cargo build, because the plugin compiles the built UI and the dataset into its binary — a plugin has no resource directory to read them from. npm run plugin:build does both in order, and the bundled-content gate refuses a binary missing either, so the failure is a message rather than a blank window.
